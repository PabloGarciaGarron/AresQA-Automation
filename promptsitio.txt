Actúa como un desarrollador Full Stack Senior en .NET y crea una aplicación web monolítica completa y lista para producción llamada **Ares**. 

El sistema debe permitir gestionar autenticación, roles, empresas, personas, solicitudes de servicio y administración de usuarios, operando con una arquitectura híbrida de Razor Pages para el frontend y controladores REST para el backend.

---

### 1. STACK TECNOLÓGICO Y ARQUITECTURA
- **Framework:** ASP.NET Core 8 (`net8.0`, C# 12).
- **Frontend:** Razor Pages con Bootstrap 5.1.0 y JavaScript nativo (Fetch API, sin Node.js, npm ni bundlers externos).
- **Persistencia:** Entity Framework Core 8 con SQLite embebido (`Data/aresqa.db`).
- **Autenticación & Permisos:** ASP.NET Core Identity con cookies (`AresQA.Session`), roles (`Administrador` y `Operador`) y bloqueo tras 5 intentos fallidos (5 minutos).
- **Seguridad Antiforgery:** Validación global de tokens CSRF (`AutoValidateAntiforgeryTokenAttribute`, header `X-CSRF-TOKEN` y endpoint `/api/auth/csrf`).
- **Documentación de API:** Swagger / Swashbuckle configurado en `/swagger` con un script JavaScript interceptor que inyecte automáticamente el token CSRF en peticiones de escritura.
- **Servidor:** Configurado para escuchar en `http://localhost:5080`.

---

### 2. MODELO DE DATOS Y REGLAS DE ENTIDADES

1. **Empresa (`Company`):**
   - `Id`: Autonumérico (código visual `EMP-0001`).
   - `Nit`: Requerido, único, de 5 a 15 dígitos numéricos (`^[0-9]{5,15}$`).
   - `Nombre`: Requerido, entre 2 y 120 caracteres.
   - `Correo`: Requerido, formato email válido, máx. 120 caracteres.
   - `Direccion`: Opcional, máx. 200 caracteres.
   - `Telefono`: Opcional, formato telefónico válido, 6 a 20 caracteres.
   - `CreadoEn`: DateTime UTC.

2. **Persona (`Person`):**
   - `Id`: Autonumérico (código visual `PER-0001`).
   - `Documento`: Requerido, único, de 5 a 20 caracteres alfanuméricos o guiones (`^[A-Za-z0-9-]{5,20}$`).
   - `Nombres` y `Apellidos`: Requeridos, entre 2 y 80 caracteres.
   - `Correo`: Requerido, email válido, máx. 120 caracteres.
   - `Telefono`: Opcional, 6 a 20 caracteres.
   - `EmpresaId`: Nullable (FK a `Company` con `DeleteBehavior.Restrict`).
   - `Activo`: Booleano (por defecto `true`).
   - `CreadoEn`: DateTime UTC.
   - *Regla:* Una persona inactiva no puede ser editada. Solo el `Administrador` puede desactivar (baja lógica).

3. **Solicitud de Servicio (`ServiceRequest`):**
   - `Id`: Autonumérico (código visual `SOL-0001`).
   - `PersonaId`: Requerido (debe ser una persona activa y tener empresa asociada).
   - `EmpresaId`: Requerido (debe coincidir con la empresa asociada a la persona).
   - `Asunto`: Requerido, entre 5 y 120 caracteres.
   - `Descripcion`: Requerido, entre 10 y 2000 caracteres.
   - `Estado`: "Pendiente" (inicial), "Aprobada", "Rechazada".
   - `Version`: Entero para control de concurrencia optimista (`IsConcurrencyToken`, inicia en 1 y se incrementa en cada cambio).
   - `CreadoPor`, `CreadoEn`: Usuario y fecha UTC.
   - `ResueltoPor`, `ResueltoEn`, `Observacion`: Datos de resolución. Si el estado es "Rechazada", la observación es obligatoria (máx. 500 caracteres).
   - *Regla:* Una solicitud resuelta no puede editarse ni reabrirse. Si al aprobar la persona está inactiva, debe rechazar la operación con error 409. Solo el rol `Administrador` puede resolver.

4. **Código de Usuario (`UserCode`):**
   - `Id`: Autonumérico (secuencia permanente con formato `USU-0001`).
   - `UserId`: FK a `AspNetUsers`.

### 3. API REST (CONTROLADORES)
Implementa controladores API bajo el prefijo `/api/`:
- **Auth (`/api/auth`):**
  - `GET /api/auth/csrf`: Retorna `{ token: "..." }`.
  - `POST /api/auth/login`: Autentica con email y contraseña, establece la cookie de sesión.
  - `POST /api/auth/logout`: Cierra la sesión (`[Authorize]`).
  - `GET /api/auth/me`: Retorna código USU, correo y rol del usuario activo.
- **Empresas (`/api/empresas`):**
  - `GET /`: Listado paginado con búsqueda (`buscar`, `pagina`, `tamano`).
  - `GET /{id}`: Detalle de empresa.
  - `POST /`: Crear empresa (valida NIT único, devuelve 201).
  - `PUT /{id}`: Editar empresa.
- **Personas (`/api/personas`):**
  - `GET /`: Listado paginado con filtros (`buscar`, `activo`, `pagina`, `tamano`).
  - `GET /{id}`: Detalle de persona con nombre de empresa.
  - `POST /`: Crear persona (devuelve 201).
  - `PUT /{id}`: Editar persona activa.
  - `PATCH /{id}/desactivar`: Baja lógica (`[Authorize(Roles = "Administrador")]`, devuelve 204).
- **Solicitudes (`/api/solicitudes`):**
  - `GET /`: Listado paginado con filtros (`buscar`, `estado`, `pagina`, `tamano`).
  - `GET /{id}`: Detalle completo de la solicitud incluyendo número de versión.
  - `POST /`: Crear solicitud pendiente (deriva la empresa de la persona, devuelve 201).
  - `PUT /{id}`: Editar solicitud pendiente (requiere versión actual; 409 en conflicto).
  - `POST /{id}/resolver`: Aprobar o rechazar (`[Authorize(Roles = "Administrador")]`, requiere versión; valida motivo si es rechazo).
- **Usuarios (`/api/usuarios`):**
  - `[Authorize(Roles = "Administrador")]`
  - `GET /`: Lista todos los usuarios con código `USU-xxxx`, email y roles (sin contraseñas).
  - `POST /`: Crea usuario con contraseña segura (mayúscula, minúscula, número, símbolo, mín. 8 caracteres) y rol canónico (`Administrador` u `Operador`). Asigna código USU en una transacción.

### 4. INTERFAZ WEB (RAZOR PAGES Y FRONTEND)
Crea una interfaz limpia, responsiva y moderna con Bootstrap:
1. **`_Layout.cshtml`:** Barra de navegación superior con enlaces según el rol (`Personas`, `Empresas`, `Solicitudes`, `Usuarios` solo para admin, botón de Cerrar Sesión y usuario actual).
2. **`Login.cshtml`:** Formulario de inicio de sesión con alertas de error y bloqueo temporal.
3. **`Index.cshtml` (Personas):** Tabla con buscador, filtro de activos/inactivos, paginación, modal o formulario de creación/edición, selector de empresa y botón para desactivar (solo admin).
4. **`Empresas.cshtml`:** Tabla de empresas, buscador por NIT/Nombre, paginación, creación y edición.
5. **`Solicitudes.cshtml`:** Listado de solicitudes con filtro de estado (Pendiente, Aprobada, Rechazada), formulario de nueva solicitud (autocompleta y bloquea la empresa según la persona seleccionada), modal de edición y modal de resolución (Aprobar / Rechazar con motivo).
6. **`Usuarios.cshtml` (Solo Administrador):** Tabla de usuarios registrados con su código USU y formulario para crear nuevas cuentas asignando rol.
7. **`lab.js`:** Utilidad compartida de JavaScript que maneje automáticamente:
   - Inyección de cabecera `X-CSRF-TOKEN` obtenida de `/api/auth/csrf` para métodos POST, PUT, PATCH.
   - Manejo de redirección a `/Login` ante errores 401.
   - Paginación y visualización de mensajes de éxito/error.
